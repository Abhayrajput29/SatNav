## Product outcome

Build SATNAV as a map-first, sourced event-intelligence website: **“Explore the world. Understand what is happening.”** The interactive map must work independently of event APIs: render the basemap and enable pan/zoom first, then load event layers and details progressively. SATNAV will show what a source reported, when the event occurred, when the report was published/updated, how precise its location is, and when SATNAV last fetched it. It will not claim complete global coverage, safety status, or guaranteed real-time delivery.

## Implementation approach and constraints

The initialized project is a new Local First Webdev project using the `web-db-user` starter: React 19, TypeScript, Vite, Express, tRPC, Drizzle ORM and the managed MySQL-compatible database. Reuse these components rather than introducing another framework. The starter's `client/src/components/Map.tsx` is a generic Google Maps wrapper that depends on the platform browser config and has no SATNAV event layers; the current demo `Home` page does not mount it. Preserve that wrapper, but use MapLibre for SATNAV's product map because the approved vector-source, event-layer and native-clustering needs are not implemented by the generic wrapper. Install MapLibre through the pinned pnpm workflow and keep dependencies reproducible in `pnpm-lock.yaml`.

Use the exact verified OpenFreeMap MapLibre style `https://tiles.openfreemap.org/styles/dark` as the initial basemap; `fiord` is an optional alternative. Keep MapLibre's visible attribution control enabled and cite OpenStreetMap/OpenMapTiles. The public tile service is free but provided as-is with no availability guarantee or SLA, so show a useful basemap error state rather than blocking the rest of the UI.

Use the existing managed MySQL database for normalized public event records, source/ingest status and deduplicated event clusters. Store WGS84 longitude/latitude separately, retain validated source geometry only when actually supplied, and use time/category/source plus coordinate indexes for capped viewport/time queries. Split antimeridian-crossing viewports correctly; do not invent geometry or coordinates. Keep schema changes additive and migrations deterministic. The managed database is shared by development and publication, so tests must not seed or delete shared production-visible data and no destructive migration will be used.

## Source policy and first integrations

Provider access was checked against primary documentation. The implementation will keep a modular source registry, per-provider health/freshness, attribution, error isolation and credential gates:

| Source | Planned use | Access and product boundary |
| --- | --- | --- |
| USGS ComCat GeoJSON | First active layer for earthquakes, magnitude, tsunami flag, event time and source detail | Public documented feeds; the official rolling feeds update every minute. Use conservative server-side caching, preserve `time`/`updated`, and never imply uniform detection or coverage. Sources: [USGS GeoJSON feeds](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php), [feed lifecycle](https://earthquake.usgs.gov/earthquakes/feed/policy.php). |
| GDACS | Public sudden-onset hazard layer, using documented event-list and geographic query endpoints | Public GET interface; respect the maximum 100 records/page and official warning that model-generated alerts can be uncertain, incomplete or delayed; link local/national authoritative sources and do not present GDACS as a substitute for official alerts. Sources: [GDACS OpenAPI](https://www.gdacs.org/gdacsapi/swagger/v1/swagger.json), [terms of use](https://www.gdacs.org/Documents/2025/GDACS_Terms_of_use_Mar_25.pdf). |
| GDELT DOC 2.0 | Sourced news/article discovery and related coverage; publisher links and reported publication times | Public URL-based search. Treat results as coverage, not verified incident records. Do not place a story on the map unless its own source provides suitable coordinates or a separate, clearly labeled geocoder result does. Respect publisher rights; cite GDELT. Sources: [DOC API guide](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/), [GDELT use terms](https://gdeltproject.org/about.html). |
| NASA FIRMS | Adapter boundary for satellite active-fire/thermal-anomaly detections | API requires a free `MAP_KEY`; none is configured or live-tested. Keep it server-side and inactive until a key is supplied through protected configuration. Use viewport-bounded queries (the API supports up to 5 days; whole-world VIIRS can return tens of thousands of points per day). Label detections as satellite observations, not confirmed fires. Sources: [FIRMS API](https://firms.modaps.eosdis.nasa.gov/api/), [FIRMS usage guide](https://firms.modaps.eosdis.nasa.gov/content/academy/data_api/firms_api_use.html), [NASA data-use guidance](https://www.earthdata.nasa.gov/engage/open-data-services-software-policies/data-use-guidance). |
| ACLED | No event ingestion in the initial release; retain only a disabled integration boundary and documentation | Requires myACLED authentication and is subject to restrictive content-use terms, including a prohibition on competing/functional-substitute products and limitations involving AI/ML. Do not retrieve, redistribute, store or send ACLED data to the SATNAV explainer unless ACLED confirms this specific use in writing. Sources: [ACLED API access](https://acleddata.com/api-documentation/getting-started), [content usage terms](https://acleddata.com/contentusage), [EULA](https://acleddata.com/eula). |

Only real provider responses may be displayed as live. Fixtures are test-only. Failed providers must leave other layers usable; valid cached records may remain visible with their age and a stale/incomplete label. The UI should distinguish officially reported, single-source, unverified, conflicting, historical, forecast and warning states where the underlying data supports those labels. Do not invent severity scales or aggregate counts that hide coverage differences.

## Search and geography behavior

Support local event/article searches, saved-place matches, direct coordinate parsing and place lookup. External geocoding will use a provider boundary with the public Nominatim service as the initial option only for explicit user-submitted searches. The official policy allows at most one request per second across the application, requires identifying User-Agent/Referer and OSM attribution, and expressly forbids autocomplete. Therefore external lookup will not fire while the user types; local event/history suggestions may be immediate, while remote lookup runs only on submit, is rate-limited/cached and can be switched to another provider. Never send confidential/personal text to geocoding. Label geocoder output as a place result, not as an incident location. Sources: [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/), [Search API](https://nominatim.org/release-docs/latest/api/Search/).

Event requests will be viewport-, time-, category- and source-bounded; debounce/cancel obsolete map requests, preserve existing content while refreshing, deduplicate in-flight requests and cap/paginate results. Keep map and list filters synchronized. Store event time, publication time, provider update time and fetch time separately in UTC; show an explicit display timezone. Support the requested time presets and custom range only where each source has data. The timeline must identify historical versus ongoing/forecast content and must not extrapolate missing history.

## Experience and feature scope

Create a full-screen map workspace with a compact SATNAV header (location/event search, time range, layer controls and settings), a collapsible left rail (layer groups, places, saved views, history and recent items), an interactive central map, a contextual event/place detail drawer, source-health/freshness indicators and a collapsible bottom timeline. Keep selected information compact enough that the map remains usable. The selected-event view will show source-reported facts, known/unknown details, available impacts, related items and real publisher/source links; all times, precision, status and provenance remain visible. A user-triggered “Explain this event” action may call the built-in Manus LLM only with retrieved records and permitted excerpts. Render model output separately from source claims; citations and links are rendered from validated server records, not invented by the model. If evidence is insufficient, say so. Do not call the LLM automatically on every map update.

Saved places, recent searches and map views can remain in browser-local storage in this release. Do not add login solely for appearance. Notification/alert subscriptions, continuously monitored feeds, mobile push and unlicensed conflict datasets are out of scope until an authorized delivery provider and credential/legal requirements exist. The layer taxonomy may provide clear “not connected” status for categories without a verified source, but it must not imply live coverage for them.

## Design direction

**Design movement:** restrained dark geospatial command console, with editorial cartography rather than a generic analytics dashboard. **Core principles:** map-first; source before narrative; uncertainty made legible; high information density without visual alarm. **Color philosophy:** near-black/navy canvas and charcoal panels create quiet contrast; electric cyan (`#56D4FF`) is SATNAV's signature signal for selected/active navigation; violet/cyan accents differentiate categories but never substitute for icons, shapes or readable labels. **Layout paradigm:** full-bleed map with lightweight, retractable instrument panels and a low-profile time rail. **Signature elements:** a fine coordinate-grid/status motif; compact source/freshness badges; distinct category glyphs and cluster rings.

Use a restrained 120–180 ms interaction motion, no flashing alerts, and honor reduced-motion preferences. Use IBM Plex Sans for interface text with IBM Plex Mono for coordinates/timestamps, with local/system fallbacks. Position the brand as a grounded global event map for people who need geographic context without pretending to be an official warning service; personality: **grounded, alert, unflustered**. Brand voice: concise and attributed (e.g. “What changed. Where. According to whom?” and “Reports are current; coverage is incomplete.”). Create a distinctive SATNAV wordmark with a custom compass-bracket/longitude arc mark rather than a default-font logo or globe clipart.

## Project structure

Extend the actual starter in place:

- `client/src/pages/Home.tsx`: assemble the single map-workspace route already registered in `client/src/App.tsx`.
- `client/src/features/map/`: MapLibre lifecycle, view state, map controls, clustering and source layers.
- `client/src/features/events/`, `search/`, `timeline/`: typed event list/detail, source status, filters, local history and submitted place search.
- `client/src/components/`: shared shell, responsive panels, tooltips and accessible controls; reuse the existing UI components.
- `client/public/manus-routes.json`: declare the real route set before the first dev-server start (initially `/` only; event/place state belongs in the URL query rather than fabricated route IDs).
- `shared/satnav.ts`: shared Zod schemas and normalized event/viewport/filter types.
- `server/providers/`: isolated USGS, GDACS, GDELT and credential-gated FIRMS adapters; ACLED remains disabled pending written approval.
- `server/events/`: normalization, coordinate/time validation, source attribution, caching, deduplication, cluster formation and MySQL viewport queries.
- `server/routers.ts` plus `server/routers/satnav.ts`: tRPC endpoints for viewport events, event/source detail, source health, location lookup and event explanation.
- `drizzle/schema.ts` and additive migrations: normalized events, source records, clusters, provider status and bounded AI explanations, preserving nullable fields and provider IDs.
- `docs/data-sources.md`: final source coverage, actual integration status, legal/key gates, attribution, refresh behavior and setup instructions; `.work/provider-research.md` remains a working evidence note.
